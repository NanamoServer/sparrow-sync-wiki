## 零阻塞的进服与退服

玩家数据的读写是 IO 密集型工作：数据库查询、NBT 编码、压缩。Sparrow Sync 把这些阶段全部移出热路径——服务器的 tick 线程和 Netty 网络线程永远不会等待数据库。

### 进服——玩家到达之前数据已就绪

1. **连接配置阶段（异步）**——Paper 一把连接交给异步的配置阶段，登录门就接管该连接，玩家此时还不会进入世界。
2. **并行预读（异步线程）**——本地原版玩家文件与远端最新快照同时读取，并在异步线程上合并出最终登录数据。
3. **放行登录门**——两份数据齐备后放行；若读取失败或超过配置的超时时间，则拒绝该次登录并记录原因。
4. **应用（玩家所在线程）**——`PlayerJoinEvent` 触发时数据已在内存中准备完毕，应用只是玩家线程上的一次短暂纯内存操作，没有 IO，没有等待。

### 退服——原版保存之后再采集，后台完成写库

1. **`PlayerQuitEvent`**——事件内只立即标记会话停止接受新的保存请求，不做任何重活。
2. **下一个 Region tick（玩家所在线程）**——采集严格排在原版写完自身玩家文件之后，保证采到的是完整状态。
3. **异步串行流水线**——编码、压缩、写库全部异步执行；同一玩家的任务严格按顺序处理，最终保存完成后才释放会话锁。

:::note

tick 线程与 Netty IO 线程全程不执行任何数据库 IO、编解码与网络等待——只有玩家所属线程上的短暂内存操作，其余工作都在异步线程上完成。

:::

## 登录门与会话锁

- **登录门**——数据没有真正就绪，玩家就无法完成登录。读取失败或超时都会拒绝登录并记录原因，而不是放玩家带着过期或空数据进服。
- **分布式会话锁**——Redis 协调玩家会话的归属，同一个账号永远不会在两台服务器上同时处于同步状态。

## 更多亮点

- **🖥️ 快照管理菜单**——在游戏内浏览快照、查看内容、恢复历史数据、固定记录和导出快照
- **📦 快照压缩**——使用 Sparrow NBT 保存玩家数据，支持 **Zstd**、Deflate 和不压缩三种格式
- **🗺️ 地图同步**——在服务器之间共享地图数据，同步模式与交互限制均可配置
- **🔧 数据恢复工具**——本地异常档案，加快照导入、导出和批量归档命令
- **🔄 数据迁移**——一条命令即可从 **HuskSync** 或 **InvSync** 迁移现有数据
